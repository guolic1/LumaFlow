# PIC/FLIP 六边形液体显示设计

## 需求与验收

来源：用户要求试用 PIC/FLIP，并了解计算负载；已确认 LED 正六边形、位号从右到左及从下到上增加，IMU X 向右、Y 向下。范围为默认运行的无灰度液体效果和只读性能查询，不改变已有扫描、IMU 或 OTA 契约，不自动烧录。

- AC-001：连续粒子通过 MAC 网格完成速度转移、压力投影和 PIC/FLIP 混合，受 IMU 板面加速度驱动，粒子不越过六边形边界。
- AC-002：输出 217 个开关像素，符合用户确认的位号方向；保留 100Hz LED 刷新与 100Hz IMU 读取。
- AC-003：无动态分配、无浮点；固定规模和迭代上限，计算分段允许主循环处理 IMU/串口；传感器无效或过期时冻结画面。
- AC-004：通过只读串口查询实际计算耗时和漏处理模拟周期，明确区分板上测量与主机测试。

## 实现

使用 13×13 单元的笛卡尔 MAC 网格、64 个等质量粒子、12 次压力迭代、90% FLIP/10% PIC，固定模拟步长 20ms。连续坐标和速度为 Q10；速度单位为单步位移，限速 0.5 单元/步。重力输入使用 `(-raw_x, -raw_y)`，保留大小并缩放为视觉效果加速度；不是按毫米标定的物理模型。仅低通板面分量，不归一化。初始粒子在容器下部规则铺放。

流程：积分和六边形碰壁 → 一次粒子分离 → 双线性 P2G 加权累加与归一化 → 保存投影前网格速度 → 压力投影（含局部过密的漂移补偿）→ 双线性 G2P，混合 PIC 速度和 FLIP 速度增量。压力使用原地速度投影，不存储压力数组。粒子用六个平面限制；压力网格以覆盖六边形的单元掩码近似斜边，不声称精确切割单元求解。

网格累加器与当前/旧速度复用 union；权重、单元类型/密度、渲染密度复用工作区，仅在相应阶段访问。模拟状态预算 3.5KB，另有 217 字节输出和少量调度统计。最终以 ARM 链接结果确认 RAM，并检查栈用量。粒子分离按 8 个粒子、转移按 16 个粒子、投影按一次迭代分段，不关中断。性能不能从桌面运行时间换算为 MCU 时间。

`fluid_effect` 在主循环使用 TIM3 调度，正常每两个 tick 启动一步。计算未完或显示背压时不累积补算，记录漏周期；等待显示期间保留待提交帧。IMU 状态非 OK、未就绪、未有效或样本超过 100ms 时暂停，不使用故障缓存驱动新运动。进入 Bootloader 仍走已有停止/复位流程。

LED 坐标按每行 9→17→9 生成，D1 位于下行右端，D109 位于中心，D217 位于上行左端。显示密度通过粒子到附近 LED 的核权重累加取阈值，不将粒子限制在 LED 中心；灰度不在本次范围内。

### 性能查询

新增 Application `GET_FLUID` (0x31)，空请求，能力 bit4；32 字节小端响应：0/4/8/12/16/20 为 uint32 的 completed_steps / last_work_us / max_work_us / last_step_us / missed_steps / max_slice_us；24 为 uint16 粒子数；26/27 为 uint8 网格宽高；28/30 为 uint16 的 state_bytes / rate_hz。work 为各计算片段和渲染的耗时之和（含抢占中断），step 为跨主循环的整步墙钟时间，包含传感器故障暂停。missed_steps 包含忙、背压、无效 IMU 等原因导致未启动的周期。查询不推进模拟。`lumaflow.ps1 -Command fluid` 解码输出，保留其他命令行为。

## Implementation Approach

foundation-first：先证明核心投影、边界、映射、持续稳定性，再接入 IMU/LED 调度和端到端只读查询。所有选择均为可逆的局部实现，不增加依赖或持久化数据，因此无需 ADR。

## 验证

- L1：CTest 验证投影降低散度、双向重力响应、所有粒子长期处于边界内、恒定粒子数、位号方向、分段完成和 RAM 预算；数值路径使用 ASan/UBSan 检查。
- L2：真实模拟核心配合假 IMU/时钟/LED，验证 50Hz 调度、背压、故障/过期冻结、恢复、计时回绕及漏周期统计；协议测试验证 0x31 字节布局、长度与能力位。
- PowerShell 模拟串口验证性能解码、无效响应、只读重试和 CLI 帮助；运行已有协议与 IMU 测试。
- Application Debug/Release 构建和栈用量检查；硬件未测时只报告规模和内存，不声称达到 50Hz。板上通过 fluid 查询耗时，并观察 IMU missed_ticks 与六边形倾斜效果。

## 实测性能问题与优化

用户板测：128 粒子配置 LastWorkUs=89129、LastStepUs=98746、MaxWorkUs=92010、MissedSteps=2587，实际约 10Hz。50Hz 只是原目标，不能视为已经达到。ARM 指令级分析的固定向右重力输入，在第 61 步观测到约 146 万条核心指令、9298 次软件除法；不模拟中断、Flash 等待和真实周期。

将 MAC 面的相邻单元存为 Flash 常量表，避免反复除以 14；粒子分离、速度回传及 LED 坐标的有界除法使用 Q20 倒数表和一次余数修正，保持 C 的向零取整。表只读，不增加 RAM；测试检查全部面映射以及除数 1..704、商 0..1024 的正负边界。1200 步差分验证中，每个阶段的粒子状态和每帧 LED 输出与旧版相同。该输入的软件除法降至 82 次。仅求解核心的 Release 改用 -O2，其他文件保持 -Os；实际收益必须板测。

随后将默认工作量降为 64 粒子、一次分离，每步从 63 片减至 31 片；粒子对检查从 16256 次减至 2016 次。为保持约相同的填充面积，初始间距从 563/488 改为 796/690、分离距离从 480 改为 680、REST_DENSITY 从 1024 改为 512，过密增益相应调整；渲染半径从 620 改为 875、核缩放从 /1024 改为 /2048，碰壁半径随粒子尺寸增加。此配置牺牲部分液体细节，以满足 MCU 的负载预算。协议布局不变；查询脚本允许 1..128 的粒子数，兼容旧固件。

相同向右重力测试的新配置为 372373 条指令、76 次软件除法，指令数减少约 75%；该比较同时包含工作量和编译优化，不是实测周期加速比。新版 Debug RAM/Flash 为 6080B/18364B，Release 为 6072B/15796B，效果状态为 3144B。RAM 包含 1KB 栈预留；Release main 帧为 176B，新增核心 Debug 单函数最大帧仍为 88B，无递归。已重新导出 300 帧实际 C 核心预览，五个重力方向稳定后约点亮 53..63 颗 LED。普通及 ASan/UBSan CTest 各 7/7 通过。误亮处理、真实模拟频率、最长片段与 IMU missed_ticks 仍需板测。

## 照片补充定位：IO16 上拉误亮

2026-10-11 照片中靠近测试焊盘的独立暗亮线，按 PCB 背面方向、外形和 USB 位置核对后，与 IO16 阳极灯 D100、D116、D132、D147、D161、D174、D186、D197、D207 相符，而非相邻的 IO17 阳极灯。R5（5.1 kΩ）连接 +3V3 与 IO16/PF2；扫描释放 IO16 时，只要上述灯的阴极输出低，R5 即可向 LED 供电。之前增加的 IO17 拉低不处理这条路径。照片对应的固件版本尚未确认，断开 R5 后的板测也未完成。

PF2 已作为 GPIO（NRST_MODE=2）使用，建议断开 R5 上拉后验证。不能简单在未使用时隙拉低 IO16，因为它也是 D209～D217 的共用阴极，会在对应阳极驱动时增加额外点亮与 IO 电流负载。仅缩短消隐或优化液体计算不能消除此持续电流路径。

## 软件验证记录

主机 CTest 7/7 与 GCC `-O2` ASan/UBSan 7/7 通过；核心覆盖双向 X/Y 重力、投影降低散度、长期变向、重叠粒子分离和位号渲染。调度测试覆盖周期、背压、故障、过期、恢复和 tick/微秒回绕。PowerShell 5.1 的 7 项脚本测试，以及 PowerShell 7 的 fluid/imu 测试通过。

首次 128 粒子实现构建：Application Debug RAM 6592B、Flash 14864B；Release RAM 6584B、Flash 12292B，RAM 数字包含 1024B 栈预留。Release `effect` 符号占 3656B。主机核心结构大小 3388B；不同 ABI 可能存在枚举对齐差异，以固件查询为准。新增核心 Debug 单函数栈最大 88B，无递归；Release LTO 内联后的 main 栈帧为 184B，仍需结合中断嵌套核对，不能将单函数帧当作整个调用链的峰值。此为优化前历史记录，新版规模与构建见上一节。
